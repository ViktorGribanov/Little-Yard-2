# Бронирование: заявки, календарь, Telegram

Что это: заявка с сайта сохраняется в `src/data/bookings.json`, попадает в админку
(раздел **Заявки**) и, если заданы ключи, уходит в Telegram. Подтверждённая заявка
занимает даты в календаре, отклонённая — освобождает.

## Как устроено

    форма на сайте
        │  POST /api/booking  { house, checkin, checkout, name, phone, comment, pet }
        ▼
    проверка (functions/_lib/booking-core.js)
        │  обязательные поля, даты, конфликт с занятыми
        ▼
    сохранение
        ├─ локально (npm run dev): запись в src/data/bookings.json
        └─ на сервере (Cloudflare Pages Function): коммит в GitHub
        ▼
    Telegram (если заданы ключи) → сообщение менеджеру
        ▼
    админка /admin → «Заявки» → статус меняется на confirmed или declined
        ▼
    сайт пересобирается: календарь показывает занятые даты

Контракт запроса и ответа один и тот же в dev и в продакшене, отличается только
хранилище — поэтому локальная проверка честно повторяет боевое поведение.

## Статусы

| Статус | Значение | Влияет на календарь |
| --- | --- | --- |
| `new` | новая, ждёт решения | да — день помечен «заявка» |
| `confirmed` | подтверждена | да — даты заняты |
| `declined` | отклонена | нет — даты свободны |

Правило ночей: заезд входит, выезд нет. Гость, выехавший 17-го, освобождает ночь
с 17 на 18 — поэтому смежные брони (14–17 и 17–20) не конфликтуют.

## Ключи окружения

| Переменная | Обязательна | Что делает |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | нет | токен бота от @BotFather |
| `TELEGRAM_CHAT_ID` | нет | чат или канал для уведомлений |
| `GITHUB_TOKEN` | да, для продакшена | fine-grained token, право Contents: write |
| `GITHUB_REPO` | да, для продакшена | `owner/repo` |
| `GITHUB_BRANCH` | нет | ветка, по умолчанию `main` |

Без Telegram-ключей заявка всё равно сохраняется — в ответе приходит
`telegram: { sent: false, reason: "telegram_not_configured" }`.
Без GitHub-ключей продакшен вернёт 503 «Приём заявок ещё не настроен».

## Локальная проверка

    npm run dev
    # форма на http://localhost:4321 или напрямую:
    curl -X POST http://localhost:4321/api/booking \
      -H 'Content-Type: application/json' \
      -d '{"house":"house-1","checkin":"2026-12-20","checkout":"2026-12-22","name":"Тест","phone":"+79000000000"}'

Заявка появится в `src/data/bookings.json` и в админке. Telegram локально не
отправится без `TELEGRAM_BOT_TOKEN` в окружении — это ожидаемо.

## Тестовые заявки

В `src/data/bookings.json` лежат девять демонстрационных заявок: пять
подтверждённых (занимают даты), три новых (ждут решения) и две отклонённые.
Их удобно использовать, чтобы увидеть работу календаря и попробовать оба решения
в админке. Перед запуском сайта их нужно удалить.

## Ссылка на админку в уведомлении

Номер заявки в сообщении — ссылка на `/admin/#/collections/bookings`.
Адрес берётся из запроса, поэтому в продакшене это `https://…pages.dev`, а
локально — `http://localhost:4321`.

Telegram **не делает кликабельными** ссылки на `localhost` и локальную сеть —
это его защита. Поэтому локальные уведомления содержат адрес, который нельзя
нажать: это ожидаемо и не является ошибкой. Если нужен рабочий тап и при
локальной отправке, задайте `SITE_URL` в `.env` (например, адрес после деплоя).
